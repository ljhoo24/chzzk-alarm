# 치지직 라이브 알림 (Chrome 확장, MV3)

등록한 치지직 채널의 방송 시작을 30초 주기로 감지해 Windows 알림을 띄우고, 열어 둔 **오프라인 라이브 페이지를 방송당 탭별 1회 자동 새로고침한 뒤 그 탭으로 포커스**합니다. 열린 탭이 없으면 새 탭으로 엽니다. 설계는 [docs/구현계획.md](docs/구현계획.md)를 따릅니다.

## 설치 (개발자 모드)

1. [Releases](https://github.com/ljhoo24/chzzk-alarm/releases)에서 `chzzk-alarm-vX.Y.Z.zip`을 받아 원하는 폴더에 압축 해제(또는 이 저장소를 클론)
2. `chrome://extensions` → 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → `manifest.json`이 있는 폴더 선택
4. 설치 직후 열리는 설정 페이지에서 채널 URL을 붙여 넣어 등록(치지직 채널을 보고 있다면 툴바 팝업의 **이 채널 등록** 버튼도 가능)
5. 설정 페이지의 **초기 설정 체크리스트** 확인(Windows 알림 권한, 방해 금지 모드, 테스트 알림)

압축 해제한 폴더를 지우거나 옮기면 확장이 사라지므로 고정된 위치에 두세요. 업데이트는 새 zip을 같은 폴더에 덮어쓴 뒤 확장 카드의 새로고침 버튼을 누릅니다(설정·채널·기록은 유지).

## 기능

**감지·알림**
- 30초 주기 상태 조회, 방송당 알림 1회(송출 재시작·네트워크 오류로 인한 중복 없음)
- 알림 버튼: **30분 뒤 다시 알림**, **오늘 이 채널 알림 끄기**. 본문 클릭 시 방송 탭 열기/활성화
- 채널별 **방송 중 카테고리 변경 알림**, 제목·카테고리 **키워드 필터**(시작 때 불일치였다가 나중에 일치하면 그때 알림)
- 알림 금지 시간대, 브라우저 시작 시 진행 중인 방송 알림 여부
- 감지가 멈추면(연속 조회 실패) 배지 `!` + Windows 알림 1회 경고. 네트워크가 끊긴 경우는 알림 경고 생략

**탭 처리**
- 등록 채널의 오프라인 라이브 페이지가 열려 있으면 방송 시작 시 탭별 1회 자동 새로고침
- 방송 시작 시 **새로고침한 탭으로 포커스 전환**, 열린 탭이 없으면 **새 탭으로 열기**(채널별 on/off)
- `포커스 전환`을 끄면 백그라운드로 두고 **음소거**, 탭을 보면 자동 해제(확장이 음소거한 탭만)
- 재시작 유예·키워드 불일치·알림 금지 시간·오늘 끄기·브라우저 시작 직후에는 새로고침만 하고 포커스/새 탭은 하지 않음

**표시·기록**
- 툴바 배지(라이브 수), 팝업 라이브 목록(제목·시청자·경과 시간), 오프라인 채널의 **보통 시작 시각**·마지막 방송
- **방송 기록·통계 페이지**: 요일×시간 시작 히트맵, 주별 방송 시간, 카테고리별 시간, 방송별 최고 시청자, 방송 목록
  - 크롬이 켜져 있는 동안 관측한 방송을 기록. 꺼져 있던 동안의 방송은 다음 조회 때 마지막 방송 1건만 보충(시청자 수 없음)

**동기화·백업**
- 채널·설정을 **구글 계정(chrome.storage.sync)에 동기화**. 크롬 로그인 + 동기화 설정의 "확장 프로그램"이 켜져 있어야 함
- 용량을 넘으면 동기화를 멈추고 설정 페이지에 안내 → **JSON 파일 내보내기/가져오기**(방송 기록 포함 가능)로 백업
- 디버그 모드·동기화 여부는 기기별 설정(동기화 대상 아님)

## 동기화 용량 설계

`chrome.storage.sync` 제한: 총 100KB, 항목당 8KB, 최대 512개 항목.

- 채널 1개를 항목 1개(`ch:{id}`)로 저장해 항목당 8KB 제한을 채널 수와 무관하게 피함. 설정은 `settings` 항목 하나
- 채널 1개는 약 250~350B → **약 250~300개 채널까지** 동기화 가능(총량의 90%를 넘으면 쓰기 전에 중단)
- 방송 기록·채널 상태·이벤트 로그는 동기화하지 않음(기기별 관측 데이터이고 용량이 큼). 필요하면 파일 백업에 포함
- 용량 초과·오류 동안에는 원격 값으로 이 기기 값을 덮지 않음(동기화 안 된 변경 보호). "지금 동기화"로 재시도

## 사전 검증 결과 (2026-09-23)

| 항목 | 결과 |
| --- | --- |
| 비공식 상태 조회 | `GET https://api.chzzk.naver.com/polling/v2/channels/{id}/live-status` 로그인 없이 동작. `content.status`(OPEN/CLOSE), `openDate`, `closeDate`, `liveTitle`, `concurrentUserCount`, `liveCategoryValue` 확인. 시각은 **KST** 문자열. 방송 이력이 없는 채널은 `content: null`, 없는 채널은 `code: 404` |
| 채널 정보 | `GET /service/v1/channels/{id}` → `channelName`, `channelImageUrl`. User-Agent가 `node`면 연결이 끊김(브라우저 UA는 정상) |
| 프로필 이미지 | `nng-phinf.pstatic.net`은 CORS 헤더가 없어 알림 아이콘용 data URL 변환에 호스트 권한 추가 |
| 오프라인 페이지 자동 전환 | **미확인** — 실제 방송 시작 시점에 확인 필요 |
| 서비스 워커 로그인 쿠키 전달 | **미확인** — 팔로잉 자동 동기화(계획 4단계) 착수 전 확인 |

## 권한

`alarms`, `notifications`, `storage`(local·session·sync), 호스트 `chzzk.naver.com`, `api.chzzk.naver.com`, `nng-phinf.pstatic.net`(알림 아이콘용 프로필 이미지). 전체 탭 권한 없이 치지직 도메인 탭만 읽으며, 탭 음소거·포커스·새 탭은 추가 권한 없이 동작합니다.

  popup/                 툴바 팝업

## 테스트

```bash
npm test
```

외부 의존성 없이 Node 20+에서 실행됩니다. chrome API를 메모리 구현으로 대체해 검증 계획 T1~T12와 v1.0 기능(포커스/새 탭, 음소거, 알림 버튼, 변경 알림, 기록, 동기화·용량 초과)을 재현합니다.

브라우저에서 수동 검증하려면 설정 페이지 → **디버그 모드**를 켜고 채널별 `OPEN (새 방송)` / `카테고리 변경` / `CLOSE` / `조회 실패` 버튼으로 상태를 바꾼 뒤 **지금 폴링**을 누릅니다. 결과는 "최근 이벤트"에 기록됩니다.

## 배포용 zip 만들기

```bash
npm run package
```

커밋된 HEAD 기준으로 `manifest.json`, `src/`, `icons/`만 담아 `dist/chzzk-alarm-v{manifest 버전}.zip`을 만듭니다.

## 계획 대비 구현 결정

- **권한 6개**: 계획의 5개에 프로필 이미지 호스트 추가(알림 API가 원격 이미지 URL을 받지 않고, 해당 호스트가 CORS를 허용하지 않음).
- **새로고침은 상태 기반 판정**: 매 주기 "OPEN 채널 × 로드 시각 < openDate × reloadLog 없음"을 판정. 워커가 중간에 종료돼도 다음 주기에 이어서 처리.
- **UNKNOWN(브라우저 시작 직후)**: "이번 브라우저 세션에서 처음 관측한 채널"을 시작 직후로 봄.
- **확장이 연 탭**은 즉시 reloadLog에 기록 — 감지가 빨라 로드 시각이 시계 오차 허용 범위(10초)에 들어도 다시 새로고침하지 않음.
- **폴링 중복 실행 방지**: 워커 인스턴스는 하나이므로 메모리 플래그 사용.

기본값(설정에서 변경 가능): 새로고침 지연 3초, 재시작 유예 5분, 활성 탭 알림 생략 끔, 포커스 전환 켬, 백그라운드 탭 음소거 켬, 감지 중단 알림 켬, 채널별 탭 열기 켬, 카테고리 변경 알림 끔.
